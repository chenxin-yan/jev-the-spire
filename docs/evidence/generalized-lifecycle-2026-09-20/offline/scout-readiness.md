## Key Code

### One observation/finalization invariant already exists
`CaptureObservationCore` computes `state["waiting"]` once, enumerates legal actions, and calls `FinishObservation` (`McpMod.Contract.cs:121-170`). `DecisionInputReady` marks the shared state waiting and returns the per-input boolean (`McpMod.Contract.cs:200-205`). `FinishObservation` then clears *all* executable siblings when halted or waiting, sets `legal_actions_complete`, fingerprints state plus private action identities, and exposes one `state_version` (`McpMod.Contract.cs:207-222`). Thus the safe pattern is: semantic filters may omit ineligible alternatives; temporary/unsupported uncertainty must set waiting or throw, never silently leave a partial POST set.

### Ownership/readiness is exact and fail-closed
`ResolveObservationSelection` only returns a selector lease if the exact selector is owned by the pending operation; otherwise it emits `unowned_selection_continuation` (`McpMod.Contract.cs:181-197`). `DispatchLabel` re-captures the observation, validates the exact current label set/version, and accepts a child without releasing its parent only when `SelectionOwners.IsCurrent` succeeds (`McpMod.Contract.cs:306-318`). Selector leases require owner identity and an incomplete task (`SelectionOwnership.cs:137-150`); closed, failed, stale, duplicate and overlapping ownership are refused (`SelectionOwnership.cs:79-116,153-187`). This preserves singleton provenance and prevents adoption of a restored/foreign UI.

### Proven causal event-selection defect (not a card/event-name exception)
The immutable live record ends immediately after `choose_event_option:0`, with `unowned_selection_continuation`, `mutation_pending: true`, and zero actions (`docs/evidence/rest-readiness-2026-09-20/live/trial-2-observation.json`). The pinned native event callback creates a `BlockingPlayerChoiceContext` and invokes `CardSelectCmd.FromSimpleGridForRewards` (`/tmp/jev-general-events-native/event-core.il:213-236`); this is a real shared native context seam, not a Brain Leech-specific name.

The existing context prefix obtains an owner only for `GameActionPlayerChoiceContext`, or for the exact treasure Obtain lane; all other contexts deliberately mask inherited tokens (`McpMod.SelectionHooks.cs:89-101`). Therefore this ordinary event selector starts with no ambient owner, `SelectionBoundaryPrefix` produces no lease (`McpMod.SelectionHooks.cs:109-120`), and the next observation correctly fails closed at `ResolveObservationSelection`. This is proven mechanism; do not guess that time, visibility, or a missing card predicate caused it.

A bounded future repair, approved for writer consideration but not implemented here, is the existing shared context prefix for ordinary owned operations: when the exact active `EventOperation`/`EventEntry` identity (same run, player, room, scene, model, generation and pending root) is valid, enter that operation owner around `BlockingPlayerChoiceContext` and let the existing boundary prefix attach the returned selector Task. Do not inherit ambient tokens unconditionally and do not add a global Task hook. Crucial readiness detail: an actionable child must not wait for `EventOperation.Root` to complete; the parent root is the Task awaiting that child. `EventOperation.CanDecide` intentionally requires `Root != null`, entry setup success, captured offer Tasks and completed children, but not root completion (`EventOperation.cs:92-117`). Poll closes/renews the selector after the child completes (`EventOperation.cs:118-130`).

### Ordinary control filter interpretation
`BridgeProtocol.OrdinaryInput` accepts filter values 0/1 and rejects 2 (`BridgeProtocol.cs:80-94`); this is intentionally a hotkey-safety contract, not a universal meaning of Ignore. Rest is proven non-hotkey and transient, so it waits. Event captures initial Ignore only as a native transition receipt, then requires Stop. Shop’s container legitimately alternates Ignore/Stop around open/close, while actionable children still use the ordinary guard. Any new adapter must prove the native setter/callback and whether keyboard/focus routes remain available before classifying Ignore as waiting.

## Architecture

1. Main-thread GET and POST both enter `CaptureObservation`; errors become a halted observation, never a partial complete action set (`McpMod.Contract.cs:52-60`).
2. Context, modal/tutorial, overlay and room phase are resolved before action enumeration (`McpMod.Contract.cs:67-127`; `McpMod.StateBuilder.cs:406-551`).
3. Each surface adds actions through native model legality plus surface-specific ownership/readiness adapters. Combat/map/potion paths share `DecisionInputReady`; rest/card-reward use proven aggregate native adapters; event/reward/treasure use owned operations and exact native Task/selection receipts.
4. `FinishObservation` is the common lifecycle owner for waiting/completeness and action withholding. POST re-captures through the same path, so a stale or temporary observation cannot dispatch (`McpMod.Contract.cs:207-222,306-318`).
5. Native hooks are limited to explicit boundaries installed in `McpMod.SelectionHooks.cs:44-84`; no global Task interception, restored-room adoption, tutorial bypass or host strategy is present.

## Current defects / coverage gaps

This is generalized by the shared context seam, not by event/card name.
2. **Concrete readiness gap:** generic card/grid/hand selection silently skips `_isClickable=false` holders (`McpMod.LegalActions.cs:49-57,242-305`) without proving whether the state is semantic or temporary. This violates the desired “entire legal set” invariant if a visible legal card is temporarily unavailable. The card-reward fix cannot be copied blindly because its native false setter is specifically pinned.
3. **Concrete combat-target gap:** `AddCombatActions` silently skips a playable target when `!VisibleCreatures().Contains(target)` (`McpMod.Contract.cs:257-270`) instead of routing target unreadability through `DecisionInputReady`; this can prune a native-legal target while exposing other cards. A modest no-hook fix is to pass the observation state into this helper and make any unreadable target set waiting, while retaining `CanPlayTargeting` as semantic filtering.
4. **Unsupported classification gaps (not proven bugs):** potion `_isUsable=false`, reward-button visibility/actionability, shop slots, and treasure holder visibility lack pinned native lifecycle evidence distinguishing semantic ineligibility from temporary unreadiness. Keep their current fail-closed/semantic behavior; do not add a universal control adapter.
5. **Offline/live limit:** rest repair is offline verified but not live-certified; the recorded trial never reached rest. Evidence explicitly says the event-selection refusal is separate and no ownership authority was added (`docs/evidence/rest-readiness-2026-09-20/README.md:71-75`; implementation limitation `offline/implementation.md:76-77`).

Flip all inputs ready in a new observation; assert every legal sibling returns together and `state_version` changes. Existing production fixture pattern is `tests/check-bridge.sh:1195-1253`.

- **Card reward:** retain disabled/partial/ready/alternative-only/missing clickability matrix and parent-retained child acceptance (`tests/check-bridge.sh:1380-1423`).
- **Combat targets:** fixture a playable target set with one unreadable target; assert no target-only action is exposed and all combat siblings are withheld; with all targets readable assert the complete set and exact target identities.
