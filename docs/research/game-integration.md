# Research: Slay the Spire 2 state/action integration on macOS

## Summary

STS2 is available natively on macOS; the strongest inspected reusable option is **Gennadiyev/STS2MCP’s MIT-declared, in-process HTTP mod**, not an STS1 mod or simulator. Recommend a Mac compatibility gate and an upstream-first decision about the observed safety/observation gaps, while retaining unmodified visual control as the comparison route—not assuming either can already complete this user’s run unattended. [Official platforms](https://www.megacrit.com/faq/) · [Bridge source](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.cs) · [License declaration](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md)

Research date: 2026-09-18. Evidence below distinguishes official documentation, inspected implementation, upstream test reports, and recommendations/inference. This lane performed **no builds, code execution, game control, or Mac testing**.

## Findings

### 1. Official platform support and modding boundary

- **Official:** Steam lists Early Access release **March 5, 2026**, Windows/macOS/Linux, and US price **$24.99**. Mac minimum: macOS 12 Monterey, dual-core Intel i5, 4 GB RAM, Metal GPU/1 GB VRAM, 4 GB storage. Recommended: macOS 15 Sequoia, M1 or quad-core Intel i5, 8 GB RAM, Metal GPU/2 GB VRAM. These requirements establish native availability, not compatibility of any particular bridge. [Steam](https://store.steampowered.com/app/2868840/Slay_the_Spire_2/)
- **Official:** Mega Crit identifies **Godot**, supports Workshop/mod creation, and explicitly says STS1 mods do not port easily because the engine and architecture differ. Do not introduce CommunicationMod, Java, ModTheSpire, or STS1 BaseMod as dependencies. The FAQ is positive modding support, **not a documented guarantee for AI automation or a stable supported gameplay API**. [Mega Crit FAQ](https://www.megacrit.com/faq/)
- **Source:** STS2MCP uses the game’s `[ModInitializer("Initialize")]`, Godot scene tree, and game assemblies. Its project targets **.NET 9**, referencing local `sts2.dll`, `GodotSharp.dll`, and `0Harmony.dll`; there is no separate STS1 loader dependency. The Mac build path defaults specifically to `Resources/data_sts2_macos_arm64`, so Intel installation layout must be checked separately. [Initializer](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.cs) · [Project](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/STS2_MCP.csproj)
- **Upstream report, not our test:** Mega Crit uploader issue #10 reports Workshop-loaded C# freezes on M4 Pro/macOS 15.5/game v0.107.1, while manual installation worked. Crucially, the July 21 follow-up says Sentry was upgraded for intended release `v0.110.*`; the fetched issue remains open without confirming the user’s current build. Recommend manual installation first, but **do not portray the historical Workshop failure as proven current incompatibility**. [Full issue and follow-up](https://github.com/megacrit/sts2-mod-uploader/issues/10)

### 2. Preferred candidate: Gennadiyev/STS2MCP

**Pin/maintenance:** inspected main resolves to commit `55e064850a68f3b4cde7e5fd525bf9b2dec4e885`; source declares mod version `0.4.0`. Repository metadata shows last push July 29, 2026 and MIT licensing. README says tested against game `v0.103.2`, while action code already mentions `v0.107` changes: neither is proof against September’s installed game. [Commit ref](https://api.github.com/repos/Gennadiyev/STS2MCP/git/ref/heads/main) · [Metadata](https://api.github.com/repos/Gennadiyev/STS2MCP) · [README](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md) · [Actions](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)

**Architecture/source:** an `HttpListener` binds localhost/127.0.0.1, default port **15526**. `GET /api/v1/singleplayer` builds state on Godot’s main thread; `POST` accepts JSON with an `action` and action-specific parameters. Card play enqueues the game’s `PlayCardAction`; other operations use game commands or visible UI signals. This controls a **live rendered game**, not a headless approximation. The optional Python MCP wrapper is unnecessary if the eventual Jev executor can use HTTP. [HTTP implementation](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.cs) · [Action implementation](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs) · [Optional MCP documentation](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md)

**Coverage inspected in both state dispatch and action handlers:**

| Decision area | Existing implementation and boundary |
|---|---|
| Battle | Hand/costs/playability, HP/block/energy, powers, enemy intents, potion slots, piles, orbs and Osty; play card, potion use/discard, end turn. |
| Map | Full node graph, coordinates, reachable `next_options`, boss identity; choose reachable node by index. |
| Rewards/treasure | Claim reward, card pick/skip, relic selection, treasure relic, proceed. |
| Shop/rest/events | Inventory prices/affordability and removal; rest options; event options/dialogue, fake merchant and Crystal Sphere. |
| Multi-step choices | Grid select/confirm/cancel, upgrade previews, bundles, relic choices, in-combat hand selection and confirmation. |
| Menus | Main/singleplayer/character select, continue, tutorial popups, game-over dismissal; unknown overlays explicitly may require manual interaction. Timeline unlock handling can deliberately return `manual_action_required`. |

These are **source coverage**, not an exhaustive end-to-end compatibility result. [State builders](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.StateBuilder.cs) · [Handlers](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)

**Critical integration findings:**

- No unified legal-action list or decision-version precondition exists in the inspected singleplayer dispatcher: state exposes flags/options, and handlers validate individual actions. Hand and selection identities are **indices**; enemy `entity_id` is recomputed from surviving same-type enemies, so it can shift after a death. Numeric `combat_id` targeting is supported, but must still be checked against the current valid enemy set. [State](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.StateBuilder.cs) · [Target resolution/actions](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)
- HTTP success means **requested/enqueued**, not animation/effect completion; purchases are explicitly fire-and-forget. No idempotency key is checked. Never batch index-based plays or blindly retry a timed-out mutation. [Actions](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs) · [Dispatcher](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.cs)
- Observation is **not read-only**: state building auto-opens merchant inventories and treasure chests. Also, despite a “full player data … deck” comment, `BuildPlayerState` does **not serialize the permanent deck**. Inspect the documented compendium `current_run` before adding a duplicate export; otherwise expose the deck explicitly. [Actual builder](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.StateBuilder.cs) · [Compendium claim](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md)
- Hidden-information handling has good precedents: draw pile is sorted rather than exported in draw order, invisible powers are excluded, and hidden Crystal Sphere cells omit item contents. This is not a complete fairness proof; full-map boss fields and other model-derived fields still need UI comparison. [Builder](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.StateBuilder.cs)
- Seed support is conditional: `ExecuteCharacterSelectMenuOption` rejects seeded standard-singleplayer embark when `Lobby == null`, explicitly without starting. `continue` uses the main-menu button; no checkpoint/restore API appears in the inspected action dispatcher. Do not promise deterministic seed replay or mid-action recovery. [Menu/seed code](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)
- Security is insufficient for unattended exposure: no authentication is checked and CORS is `*`. Profile APIs include deletion, and menu actions include abandon/quit. Loopback is necessary but not sufficient; restrict the executor’s capability set and harden the mod boundary. [HTTP code](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.cs) · [Profile API documentation](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md)

### 3. Alternative: netcan/slay-the-spire2-agent

**Snapshot/maintenance:** inspected tree `3ac97a1d7a1eaa73bcacc8b04daaf1181e142b60`; GitHub metadata shows last push March 19, 2026 and **no detected license**. Treat reuse permission as unresolved, not “open repository therefore freely reusable.” [Tree](https://api.github.com/repos/netcan/slay-the-spire2-agent/git/trees/3ac97a1d7a1eaa73bcacc8b04daaf1181e142b60) · [Metadata](https://api.github.com/repos/netcan/slay-the-spire2-agent)

**Stronger contract/source:** snapshots carry `session_id`, `decision_id`, `state_version`, phase, compatibility/provider metadata; legal actions have IDs, params and target constraints. The runtime coordinator refreshes state before submission and rejects stale decisions or actions outside its current legal set. Exporters fingerprint state/action content, excluding diagnostic-only fields. These are useful design references, not a reason to import its agent strategy layer. [Contracts](https://github.com/netcan/slay-the-spire2-agent/blob/main/mod/Sts2Mod.StateBridge/Contracts/Models.cs) · [Coordinator](https://github.com/netcan/slay-the-spire2-agent/blob/main/mod/Sts2Mod.StateBridge/Providers/InGameRuntimeCoordinator.cs) · [Exporters](https://github.com/netcan/slay-the-spire2-agent/blob/main/mod/Sts2Mod.StateBridge/Extraction/WindowExtractors.cs)

**Limitations/source:** timeout after three seconds leaves the pending action queued; `request_id` is correlation, not demonstrated deduplication. Failed refresh can fall back to a cached window. Card IDs include hand slot even when an instance key exists, so do not assume persistent identity across reordering. Explicit phases include battle/reward/map/event/shop/menu/terminal; rest and arbitrary deck-selection coverage were **not established** by this audit. [Coordinator](https://github.com/netcan/slay-the-spire2-agent/blob/main/mod/Sts2Mod.StateBridge/Providers/InGameRuntimeCoordinator.cs) · [Identity](https://github.com/netcan/slay-the-spire2-agent/blob/main/mod/Sts2Mod.StateBridge/Providers/RuntimeCardIdentity.cs) · [Phases](https://github.com/netcan/slay-the-spire2-agent/blob/main/mod/Sts2Mod.StateBridge/Contracts/Models.cs)

**Upstream testing, not Mac evidence:** validation notes distinguish fixture mode from live runtime and document Windows-path/game `v0.98.3` tests. They report successful card/end-turn/reward execution, then a battle-to-next-battle run classified `success_reject_heavy`. Their runner also auto-ends turns and offers safe-default map/reward modes: **do not reuse those policies when Jev alone owns strategy**. No target-Mac evidence was found in the inspected material. [Validation record](https://github.com/netcan/slay-the-spire2-agent/blob/main/docs/prototype-validation.md)

### 4. Options, recommendation and usage

**Recommendation, not decision:** reuse STS2MCP’s singleplayer C# HTTP bridge, with the visible Steam game left running. Prefer it over netcan because licensing is declared, inspected coverage is broader, and Mac build paths exist—while recognizing those paths and the README’s cross-platform DLL statement are **project claims, not Mac run evidence**. [Project](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/STS2_MCP.csproj) · [README](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md)

**Unmodified visual alternative—inference:** official mouse-only and “playable at your own pace” support make a screenshot/input experiment reasonable. It avoids mod ABI and hidden-state leakage, but must obtain card text, legal choices, targeting and completion from the UI; expected extra inspection/recovery is a hypothesis to measure. Structured control can still be watchable because it invokes live game actions; neither route’s unattended reliability is established here. [Steam input/accessibility](https://store.steampowered.com/app/2868840/Slay_the_Spire_2/) · [Live action paths](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)

**Usage anchor, not Jev pricing:** STS2MCP’s author reports approximately **7.34M aggregate tokens/run for GPT-5.4 and slightly over 8M for Sonnet 4.6**, on Ironclad. Counting includes input/output/tool responses and is not a billing-grade benchmark. Use approximately 8M only as an initial comparison anchor, not a ceiling; record actual billed input/output/cache tokens, action count and retries in the pilot. [Author’s benchmark claim](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/README.md)

### 5. Minimum planned extension and future validation

**Candidate requirements, not an approved patch plan:** inspect supported upstream options first and report confirmed gaps to the bridge maintainer through an owner-approved contribution. A local fork or workaround requires explicit owner approval; no implementation is authorized here. Assess whether the first run needs each safeguard rather than treating this list as a mandatory framework. Keep one executor and one mutation in flight; Jev chooses every gameplay option. Add a main-thread-checked observation token, request deduplication/status, current option/target validation and explicit busy/pending-choice reporting. Make GET pure, expose chest/shop-opening actions, close the permanent-deck observation gap, and allowlist gameplay routes with local authentication/no wildcard CORS. These are **source changes to validate**, not an existing supported extension API or a new strategy engine. [Dispatcher gaps](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.cs) · [Observation gaps](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.StateBuilder.cs)

Minimum future probes, each with saved observations and visible-game evidence:

1. **Mac compatibility:** record chip/OS, Steam branch/build ID, displayed game version and assembly hashes; pin bridge SHA; manually load its DLL/manifest, verify listener and one visible action. Check Intel versus ARM paths and loader logs, not merely successful compilation. [Build paths](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/STS2_MCP.csproj) · [Mac loader history](https://github.com/megacrit/sts2-mod-uploader/issues/10)
2. **Ownership/coverage:** exercise menu → combat → rewards → map, then shop removal, rest upgrade, event, potion targeting, hand selection and confirm/cancel, death/victory. Validate fresh-profile tutorial/timeline requirements during human setup; unknown overlays must stop rather than guess. [Coverage/known stops](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)
3. **Race/fairness:** duplicate cards/enemies, hand reindexing, target death, slow animations, repeated request and timeout-after-enqueue; require stale-action rejection and no double purchase/play. Compare exported deck/piles/intents/hidden cells against UI; confirm repeated GET has no effects after hardening. [State](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.StateBuilder.cs) · [Actions](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)
4. **Recovery/comparison:** test normal saved-run continue and attempted seed setup without overwriting valuable saves; compare one bounded visual segment with structured control using interventions, completion errors, latency and billed usage. Only promote to an unattended full run after these gates pass. [Continue/seed boundary](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs)

## Gaps

Exact target Mac/game build, current Workshop-fix behavior, save/profile separation, achievement effects, comprehensive hidden-information parity, netcan reuse permission, and complete autonomous run success remain unresolved. The source does not justify promising universal overlay handling, seeded standard-singleplayer automation, or crash-safe replay. [Loader issue](https://github.com/megacrit/sts2-mod-uploader/issues/10) · [Bridge limitations](https://github.com/Gennadiyev/STS2MCP/blob/55e064850a68f3b4cde7e5fd525bf9b2dec4e885/McpMod.Actions.cs) · [Alternative metadata](https://api.github.com/repos/netcan/slay-the-spire2-agent)

Tool limitation: shared Firecrawl returned HTTP 429 rate limits; a coordinated focused batch recovered the core sources. A guessed CLI-Anything contents path returned 404 and was not treated as evidence. Two candidates’ actual source was inspected; netcan’s large reflection reader and STS2MCP’s compendium internals were not fully audited. No repository README or upstream Windows test has been promoted to machine-tested Mac evidence.
